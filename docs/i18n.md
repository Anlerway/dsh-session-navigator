# 多语言

插件界面有十种语言：中文（`zh`）、English（`en`）、日本語（`ja`）、한국어（`ko`）、
Deutsch（`de`）、Français（`fr`）、Español（`es`）、Русский（`ru`）、Português（`pt`）、
繁體中文（`zh-hant`）。

DSH 自己的语言开关只列八种（中、英、日、西、法、德、俄、葡），韩语与繁體中文没有宿主入口，
所以插件带一个自己的「界面语言」下拉（第 6 节），默认跟随 DSH。词典是数据文件，
放在 `assets/i18n/` 下，构建时内联进产物；代码里不写任何一门外语的界面文案。

## 1. 词典文件与构建

一门语言一份 `assets/i18n/<code>.json`，共十份。`scripts/build-client.mjs` 的 `@inline`
目录机制把整个目录读成对象，写进 `lib/client.js` 的 `const DICTS = { ... }`。
`lib/client-src/22-locale.js` 里对应的是占位行：

```js
const DICTS = /* @inline assets/i18n/*.json */ {};
```

`lib/client.js` 由分片构建而成（产物不进仓库），运行时不再读文件：DSH 的模块加载器直接执行
这份脚本，插件没有打包器，配置与词典都得在脚本体里。改完词典跑 `node scripts/build-client.mjs`
（`npm test` 与 CI 会自己先构建），`test/client-bundle-drift.test.mjs` 会验证磁盘上的产物能从
`lib/client-src/` 逐字节重建。

客户端从词典本身推语言清单，新增语言时不用在客户端再抄一遍：

```js
const LANGS = Object.keys(DICTS).sort();
```

## 2. 一份词典的两节

| 节 | 条数（每种语言） | 键的样子 | 谁读它 |
|---|---|---|---|
| `settings` | 226 | 具名键，如 `langCode`、`aiLang`、`langName`、`setUiLang`、`navLabel` | DSH 的 locale 服务。`LOCALE_TABLES` 按语言码装 `DICTS[code].settings`，`apply` 里一次性 `ctx.locale.register(NS, LOCALE_TABLES)`；设置页与面板都通过 `ctx.locale.bind(NS)` 取词 |
| `panel` | 465 | 中文原文，如 `"搜索范围": "Search in"` | 面板与独立窗口的 `T()`，见第 4 节 |

细化约定：

- `settings` 的键集合以 `zh.json` 为基准。`langCode` 必须等于文件名，`aiLang` 见第 5 节，
  `langName` 是这门语言自称的名字（选择器直接显示它，见第 6 节）。
- `panel` 的键集合以 `en.json` 为基准，十份都有这一节。`zh.json` 的值逐条等于键——中文的
  译文就是原文，它是源文的复本而不是译文；`zh-hant` 的键同样是简体原文，值是繁体译文。
  这条复本让十份词典结构一致，也让中文措辞可以在 `zh.json` 里改，不必去动四百多个调用点。
  `check-i18n.mjs` 因此不再为 `zh` 开例外。
- 两节各有一套占位符写法：`settings` 用 `{size}` 这类具名占位，`panel` 用 `{0}`、`{1}`。
  每个值都必须是非空字符串。

`en.json` 的两个节开头长这样：

```json
{
  "settings": {
    "langCode": "en",
    "aiLang": "en",
    "langName": "English",
    "title": "Session Navigator",
    "navLabel": "Session Navigator"
  },
  "panel": {
    "搜索范围": "Search in",
    "所有位置": "All locations"
  }
}
```

## 3. 一份清单，三处副本，一处派生

语言码从 DSH 的 locale 出发，经面板、桥、Electron helper、页面 URL，最后落到 shim 的词典。
中间三站彼此 import 不到，所以各带一份清单：

| 位置 | 形态 | 为什么不能共用 |
|---|---|---|
| `lib/lang.js` | `export const LANGS` 与 `normalizeLang()`，权威 | 插件侧的 ESM 模块 |
| `lib/detached/main.cjs` | 文件内 `const LANGS = [...]` | helper 被打进下载的 Electron 运行时，相对 import 指向不存在的目录 |
| `assets/detached/shim.js` | 文件内 `const LANGS = [...]` | 静态页里的普通脚本，没有模块加载器 |

客户端的第四份清单由第 1 节的 `Object.keys(DICTS).sort()` 现算出来，没有手抄的副本。
`test/lang-chain.test.mjs` 把这四者与磁盘上的 `assets/i18n/*.json` 钉在一起，并固定
`LANGS.length === 10`。

`normalizeLang()` 在四处是同一套规则：去掉首尾空白、转小写、下划线换成连字符、取区域前缀、
不在 `LANGS` 里就返回空串。唯一的特例是繁體中文：`zh` 后面跟 `hant`、`tw`、`hk`、`mo`
（`zh-TW`、`zh_HK`、`zh-Hant`、`zh-MO` 等）都归到 `zh-hant`，其余 `zh-*` 归到 `zh`；
`ja-JP` 归到 `ja`，`pt-BR` 归到 `pt`，`it-IT` 没有词典，返回空串。宿主侧的 `lang-changed` 命令、
`POST /detached/open` 与 `lib/detached/launcher.js` 都调这个函数归一，没有第二份判断。

## 4. 面板取词：T() 与三层回退

面板与独立窗口的短标签走 `T(中文原文, params)`。键就是中文原文，一屏渲染树里有四百多条这样的
短句，命名键会多一层间接；改字时若字典没命中，页面显示的是中文原句，不会印出键名。

`T()` 读模块级的 `panelLang`，`Panel` 每次渲染都从三处刷新它：
`panelLang = uiLangOverride || normalizeLang(t("langCode")) || panelLang`
（`lib/client-src/14-panel-open-tabs-filter.js`）。`uiLangOverride` 是插件自己存的语言（第 6 节）。
语言开关一动，DSH 用新的 `t` 重渲染插槽，下一帧就是新语言。代价是模块级表（`FIXED_META`、
`COLUMNS`）的 `label` 必须写成 `get label() { return T("…"); }`，直接赋值会在模块加载时求值、
永久冻在中文。

查找顺序：

1. `panelTable(panelLang)`，即 `DICTS[lang].panel`，命中就用它。中文也走这一步，只是它的
   值等于键。
2. `panelDict()`，缓存着的英文表（`panelLang` 是 `zh` 时跳过，中文原文已经是答案）。
3. 都没有就回落到中文原文。

第 2 步的英文兜底是给「词典有、这门语言还没有这一条」的时刻用的：日文读者看到英文，
比看到中文更接近能读的内容。占位符由 `T()` 替换，`{0}`、`{1}` 与调用点的参数一一对应。

相对时间另有一张正字法表：`SPACED_UNIT_LANGS`（`lib/client-src/07-http-format-icons-copy.js`）
里是 `en`、`de`、`fr`、`es`、`ru`、`pt`，这些语言写「3 天」中间留空格；`zh`、`zh-hant`、
`ja`、`ko` 连写「3天」。

## 5. uiLang() 与 aiLang()

两个函数都在 `lib/client-src/07-http-format-icons-copy.js`，回答的是两个不同的问题。

`uiLang()` 返回窗口语言，取值是 `LANGS` 里的十个码之一。第一优先是插件自己存的语言
（`uiLangOverride`，第 6 节），其次才看 `ctx.locale.bind(NS)("langCode")`，
归一失败就回落到 `panelLang`，再回落到 `zh`。它用在语言离开面板的地方：
`POST /detached/open` 的 body，以及 `lang-changed` 命令——独立窗口跟着面板的语言走，
哪怕 DSH 自己是另一种语言。

`aiLang()` 返回 AI 提示的语言，只认 `zh` 与 `en`。它同样先看 `uiLangOverride` 对应的词典，
再读当前词典的 `settings`：`zh` 与 `zh-hant` 写 `zh`，其余八份都写 `en`。宿主侧的提示词只有
两个分支：`lib/host/summarize.js` 按 `meta.lang === "en"` 走英文，`lib/domain/summaries.js`
的 `systemPrompt(lang)` 以 `lang === "en"` 区分中英两套模板。所以日文界面的 AI 摘要用英文提问，
返回也是英文。界面语言不受这个限制，受限的只有提示词这一层。

调用点：`lib/client-src/02-launch-and-ai-fields.js` 的 `summarizeSessions(ids, titles, aiLang())`；
`lib/client-src/21-search-index.js` 里也有一处按 `aiLang()` 判断的分支。

## 6. 插件自己的界面语言（ui.lang）

宿主只认得它自己语言档里的八种，韩语与繁體中文选不到；反过来说，用户也可能想在这个插件里
用与 DSH 不同的语言（DSH 是英文、面板要中文）。所以插件存一个自己的选择：

```js
// lib/domain/settings.js
export const UI_LANGS = Object.freeze(["auto", ...LANGS]);
defaultSettings()      // ui: { lang: "auto" }
normalizeSettings()    // 不在 UI_LANGS 里就回落 "auto"
```

`auto` 是默认值，含义是「跟随 DSH」——此时 `uiLangOverride` 是空串，取词完全回到第 4、5 节
的宿主链路。选了一个具体语言码之后，客户端这样收：

```js
// lib/client-src/07-http-format-icons-copy.js
let uiLangOverride = "";
function applyUiLang(settings) {
  uiLangOverride = normalizeLang(settings?.ui?.lang);
  if (uiLangOverride) panelLang = uiLangOverride;
  return uiLangOverride;
}
```

`applyUiLang()` 在两处被调用，都拿到刚读回来的 `/settings`：

- `Panel`（`lib/client-src/14-panel-open-tabs-filter.js`）：每次渲染都从 `boot.data.settings` 里读，
  与日期格式、大小单位同一批；
- `SettingsSection`（`lib/client-src/21-search-index.js`）：下拉框的 `onChange` 先写
  `PUT /settings { ui: { lang } }`，落地后再 `applyUiLang`：面板每次渲染都读这个模块级变量，
  关掉设置页回到面板，文字已经换了，不必重启 DSH。

下拉框在设置页「显示」组的第一行，`<select className="se-set-select">`：第一项是
`t("setUiLangAuto")`，其余按语言码顺序（也就是词典目录的顺序，`Object.keys(DICTS).sort()`）
列出 `DICTS[code].settings.langName`。
下拉框比一排 chip 省宽度：十一种选项横排会撑破对话框。语言名存在词典里
（`settings.langName`），选择器就按那门语言自己的写法列出语言——繁體中文的名字不是谁的译文；
写成字面量还会撞上 `test/panel-copy.test.mjs` 对渲染源码里裸中文的禁令。

新加的四条 `settings` 键：`langName`（自称）、`setUiLang`（标签）、`setUiLangHint`（说明）、
`setUiLangAuto`（跟随 DSH 那一项）。十份词典都有，简体中文的四条是
「简体中文 / 界面语言 / 面板自身文字使用的语言。跟随 DSH 就用宿主当前的界面语言。/ 跟随 DSH」。

`test/ui-lang.test.mjs` 钉住这条链：文档侧的默认值与枚举、非法码回落，客户端侧的
`applyUiLang` 返回值、`T()` 是否读到对应表、繁中是否归到 `zh-hant` 与 `aiLang()` 是否为 `zh`、
十种语言的自称互不相同。

## 7. 独立窗口：语言走 URL

窗口有自己的一份 document，看不到 DSH 的语言开关，也不能跟着 DSH 重渲染。链路是：

1. 面板把 `uiLang()` 放进 `POST /detached/open`，`lib/index.js` 用 `normalizeLang` 收下；
2. `lib/detached/launcher.js` 归一后写进 helper 的环境变量 `DSH_SE_LANG`；
3. `lib/detached/main.cjs` 的 `pageUrl()` 拼出 `?lang=<code>`；
4. shim 从 URL 读出 `LANG`，同一套 `normalizeLang` 规则，认不出就是 `zh`。

因为第 1 步取的是 `uiLang()`，独立窗口的语言与面板一致：在插件里选了日文，DSH 是英文，
弹出来的窗口也是日文。进入窗口的是 `settings` 那一节：面板注册词典时
`locale.register(NS, LOCALE_TABLES)` 把十份 `settings` 表写进 shim 的 `dictionaries`，
shim 的 `translate()` 按 `LANG` 取当前表，缺键时依次试英文表、中文表，最后回落到键本身。
窗口里面板自己画的句子在渲染时已由 `T()` 查 `panel` 表翻好，到 DOM 时是成品文本。
shim 自带的那十几行界面文案（启动标题、启动语）走 `L(zh, en)` 二分支，
它们在面板渲染之前就要出现，那时还拿不到词典；`LANG` 不是 `zh` 时按英文出，再由 shim 改写
`document.title` 与启动语。`index.html` 也按中文首发。

中途换语言时，面板经命令总线发 `lang-changed`，控制器在控制通道广播 `{ type: "lang" }`，
helper 直接 `win.loadURL()` 重载页面。字典在页面加载时定死，重载是唯一让它换掉的方式。

## 8. 新增一门语言

1. 复制 `assets/i18n/en.json` 为 `assets/i18n/<code>.json`，把 `settings.langCode` 改成
   `<code>`，`settings.aiLang` 写 `en`（中文与繁體中文写 `zh`），`settings.langName` 写这门语言
   自称的名字。繁體中文这类与简体共用一套 key 的语言，`panel` 键照抄简体原文、值写译文。
2. 翻译 226 个 `settings` 键与 465 条 `panel` 条目，占位符原样保留。两条硬规则：
   键集合与基准一致，值非空。
3. 把语言码加进 `lib/lang.js` 的 `LANGS`，并同步 `lib/detached/main.cjs` 与
   `assets/detached/shim.js` 里的同名常量。若这门语言有多个常见区域码（如繁體中文的
   `zh-TW`/`zh-HK`），在四份 `normalizeLang` 副本里加映射。
4. 决定它是否进 `SPACED_UNIT_LANGS`（第 4 节），按该语言的正字法判断数字与单位之间留不留空格。
5. 跑 `node scripts/build-client.mjs` 重建 `lib/client.js`，产物里的 `DICTS`、派生出的
   `LANGS` 与 `LOCALE_TABLES` 才会带上新词典；界面语言下拉与 `UI_LANGS` 自动多一项。
6. 给 `locale/<code>.json` 补一份插件市场元数据：`{ "meta": { "title": …, "description": … } }`，
   标题用该语言词典的 `settings.title`。`locale/` 是 DSH 插件列表读的东西，与界面词典互不影响，
   但 `check-i18n.mjs` 要求两份文件同集合、两个字段都非空。
7. 改 `test/lang-chain.test.mjs` 里 `LANGS.length` 的断言（现在钉的是 10），
   以及 `test/i18n-render.test.mjs` 里的语言循环与自称列表。
8. 跑 `node scripts/check-i18n.mjs`，再跑
   `node --test test/lang-chain.test.mjs test/panel-copy.test.mjs test/locale-parity.test.mjs test/i18n-render.test.mjs test/ui-lang.test.mjs`。

## 9. 门禁

| 命令 | 检查什么 |
|---|---|
| `node scripts/check-i18n.mjs` | 磁盘上的词典集合等于 `lib/lang.js` 的 `LANGS`；每份 JSON 可解析；`langCode` 等于文件名；`aiLang` 符合第 5 节的规则；`settings` 键集合对 `zh.json`、`panel` 键集合对 `en.json` 无缺无多；占位符集合一致；值都是非空字符串；`locale/<code>.json` 与词典同集合且 `meta.title`、`meta.description` 非空。加 `--json` 出机读结果，退出码非零即失败 |
| `test/lang-chain.test.mjs` | 三处副本、磁盘目录与产物派生的清单四者一致，`LANGS.length` 为 10，`normalizeLang` 与桥的白名单行为 |
| `test/panel-copy.test.mjs` | `T()` 用到的每个键都在词典里，渲染树里没有裸中文字面量，占位符不丢 |
| `test/locale-parity.test.mjs` | `zh` 与 `en` 两份 `settings` 的键集合与占位符一致（十种语言的全量校验在 `check-i18n.mjs`） |
| `test/i18n-render.test.mjs` | 十种语言各挂载一次面板，标签换成该语言的译文，非中文不残留长中文串 |
| `test/ui-lang.test.mjs` | `ui.lang` 的文档形状与回落、`applyUiLang` 与 `T()`/`aiLang()` 的联动、十种语言的自称 |
| `scripts/build-client.mjs --check` | 磁盘上的产物能从 `lib/client-src/` 逐字节重建，词典内联结果与源文件一致（产物不进仓库，CI 与 `pretest` 是直接构建而不是比对） |

`check-i18n.mjs` 直接从 `lib/lang.js` import `LANGS`，不抄清单，所以加语言时它跟着变。

## 10. 症状对照

| 看到的 | 多半是 | 改哪里 |
|---|---|---|
| 设置页某个标签印出键名 | 这门语言的 `settings` 缺键 | `settings` 节 |
| 面板某句显示中文 | `panel` 缺键，回落到中文原文 | `panel` 节 |
| 日文窗口里出现英文 | 产物没重建，`panel` 表里没有这门语言，`T()` 回落到英文表 | 第 1、4 节 |
| AI 摘要的语言与界面不同 | 词典的 `aiLang` 写错 | `settings.aiLang` |
| 在插件里选了语言，面板没变 | 文档里 `ui.lang` 没存下，或 `applyUiLang` 没被调用 | 第 6 节 |
| 独立窗口的语言与面板不同 | `POST /detached/open` 没取 `uiLang()` | 第 5、7 节 |
| `lang-chain` 红了 | 三处副本、磁盘目录、产物有一处没跟上 | 第 3 节 |
